# HASSAN Training — نسخة تطوير ومعاينة آمنة

هذه النسخة مخصصة لتطوير الواجهة والمحتوى واختبار التوافق. **ليست نشراً للإنتاج ولا تغيّر قاعدة البيانات الحالية.**

## الموارد الحالية
- Worker الإنتاج الحالي: `hassantraining84`
- قاعدة D1 الحالية: `hassan-training-db-8`
- معرّف D1: `f0ac5c4a-0aac-41fb-b505-761cac17ee88`
- الربط: `DB`
- فرع التطوير: `platform-preview-rebuild`

## ما تم بناؤه في هذا الفرع
- واجهة عامة متجاوبة للهاتف.
- مكتبة مرجعية ثنائية اللغة تضم 150 تمريناً.
- مركز معرفة رياضية يضم 8 مقالات عربية/إنجليزية مع روابط للمراجع الأصلية.
- عرض خدمات التدريب بدلاً من بيع الدورات أو الاشتراكات التعليمية.
- هوية سوداء/فضية/بيضاء.
- نموذج تقييم أولي ولوحة عميل تجريبية.

## توافق قاعدة البيانات
تم فحص مخطط D1 الحالي بقراءة فقط. الجداول الأساسية الموجودة تستخدم البنية التالية:
- `clients`: رقم عميل تلقائي، الاسم، الهاتف، البريد، تاريخ الإنشاء.
- `assessments`: العميل، الهدف، الخبرة، أيام التدريب، المعدات، الملاحظات.
- `programs`: العميل، اسم البرنامج، الوصف، الحالة، القالب، التصنيف.
- `exercise_completions`: رقم تلقائي، العميل، اسم التمرين، تاريخ الإكمال.
- `sessions`: رمز الجلسة، رقم المستخدم، انتهاء الصلاحية.

لا توجد حاجة إلى إنشاء جداول أو تشغيل migrations لهذه الوظائف الأساسية. الكود في هذا الفرع يطابق أسماء الأعمدة الفعلية ولا يحذف أو يفرغ أي بيانات.

## قفل الكتابة
`ALLOW_DB_WRITES=false` افتراضياً. هذا مقصود: لا يتم إنشاء عملاء أو تقييمات أو برامج أو سجلات إكمال حتى تنجح اختبارات المعاينة من البداية إلى النهاية. لا تغيّر القيمة إلى `true` على الإنتاج قبل التحقق من مسار الحفظ والاسترجاع والصلاحيات.

## فحص الصحة
افتح `/api/health` في نسخة المعاينة. المطلوب:
- `database: true`
- `schema_ready: true`
- `write_enabled: false`

## حدود هذه النسخة
- واجهة المدرب الحالية في Worker الإنتاج تحتوي بالفعل على تسجيل دخول ولوحات إدارة ومسارات API مستقلة. لا تستبدلها بهذا Worker المبسط ولا تدمج هذا الفرع في `main` تلقائياً.
- بوابة العميل المستقلة وتسجيل الدخول الآمن للعميل يحتاجان استكمالاً منفصلاً؛ لا تستخدم تسجيل الدخول برقم الهاتف وحده.
- مكتبة الفيديوهات تحتاج ربطاً واختباراً فعلياً؛ لا تفترض أن وجود ملفات الفيديو يعني ظهورها داخل الواجهة.
- Runway متصل لكن رصيد مساحة العمل الحالي صفر ولا تتوفر نماذج فيديو؛ لم يتم استهلاك أي رصيد أو بدء توليد مدفوع.

## قواعد الحماية
- لا تنشئ Worker أو D1 جديداً.
- لا تغيّر إعدادات Worker الإنتاج.
- لا تستخدم `DROP` أو `TRUNCATE` ولا تحذف بيانات.
- لا تنشر هذا الفرع إلى Production قبل الاختبارات والمراجعة.

## نتائج فحص الإنتاج — قراءة فقط
تم فحص Worker الإنتاج وD1 مباشرة دون إجراء أي كتابة:
- Worker الإنتاج يحتوي بالفعل على تسجيل دخول المدرب ولوحات العملاء والتمارين والملاكمة والبرامج والجلسات والتقدم والتعليم والتغذية والوسائط والمؤهلات.
- الجداول الحالية تضم 8 عملاء و9 تقييمات و10 تمارين و4 أنظمة ملاكمة و10 أساليب ملاكمة و5 مقالات في `education_articles` و7 شهادات/آراء و8 أسئلة شائعة.
- جداول البرامج والحصص وسجلات إكمال التمارين فارغة حالياً.
- يوجد اختلاف بين `education_article` (فارغ) و`education_articles` (به 5 مقالات). صفحة تعليم المدرب تحاول قراءة الجدول المفرد أولاً، ولا تنتقل إلى الجمع إلا عند حدوث خطأ SQL؛ لذلك قد لا تعرض المقالات الخمسة رغم وجودها.
- لا يوجد مسار `/api/health` في Worker الإنتاج الحالي؛ هذا المسار خاص بواجهة المعاينة الجديدة.
